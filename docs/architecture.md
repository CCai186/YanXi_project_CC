# AI 语音通话助手 — 架构详解

## 1. 项目概述

本系统是一个基于 LangChain/LangGraph 多智能体框架的 AI 语音通话助手。它部署在手机来电的"呼叫前"环节——当有人拨打机主电话时，系统在响铃之前先代接，完成以下判定：

- **诈骗电话** → 直接拒绝，不打扰机主
- **业务来电**（外卖、快递等）→ 与来电者对话，提取信息，生成摘要卡片
- **重要紧急来电**（亲友急事）→ 转接呼叫机主

## 3. 多 Agent 调度逻辑

调度器使用 LangGraph 状态机，按固定顺序流转：

```
START → 接入来电语音转文字
  ↓
[Node 1: scam_detection]
  ├── RAG 检索欺诈知识库
  ├── LLM 判定是否诈骗
  ├── 输出: {is_scam, scam_type, confidence, reason}
  ├── 条件边: is_scam==True → END (拒绝来电)
  └── 条件边: is_scam==False → 继续
  ↓
[Node 2: intent_classification]
  ├── LLM 分类: 业务来电 / 亲友紧急 / 普通来电
  └── 条件边: 按分类路由到不同 Node
  ↓
[Node 3a: business_conversation]  ← 业务来电
  ├── 多轮对话提取信息
  ├── 生成摘要卡片
  └── END
  ↓
[Node 3b: urgent_forwarding]  ← 亲友紧急
  ├── 确认身份和紧急程度
  ├── 触发转接通知
  └── END
  ↓
[Node 3c: general_reply]  ← 普通来电
  ├── TTS 礼貌回复
  └── END
```

### 为什么是这个顺序？
- **安全优先**：先做风险评估，诈骗电话不进入任何对话环节
- **业务分流**：非诈骗才分类，减少不必要的 LLM 调用
- **人工兜底**：只有确认为重要紧急才打扰机主

## 4. RAG 知识库设计

### 数据源
- **TeleAntiFraud-28k**：28,511 条音频-文本对，覆盖 12+ 种诈骗类型
- 来源：HuggingFace `JimmyMa99/TeleAntiFraud`
- 论文：ACM MM 2025

### 处理流程
1. 用 `datasets` 库加载数据集
2. 提取每条记录的文本字段（ASR 转录 + 诈骗推理标注）
3. 用 `BAAI/bge-small-zh-v1.5` 做 embedding
4. 向量存入 ChromaDB，持久化到本地磁盘
5. 检索时：query embedding → ChromaDB 相似度搜索 → 返回 top-k 案例

### 为什么用 ChromaDB？
- 轻量级，无需部署外部服务
- 支持本地持久化，重启不丢失
- Python 原生集成，与 LangChain 完美配合

## 5. 语音模块设计

### STT（语音→文字）
- 模型：Faster-Whisper medium（基于 OpenAI Whisper，CTranslate2 优化）
- 语言：中文
- 设备：GPU (CUDA)，也支持 CPU 回退
- VAD（语音活动检测）：检测说话开始和结束，自动分段

### TTS（文字→语音）
- 引擎：Edge-TTS（微软 Edge 浏览器内置引擎）
- 语音：zh-CN-XiaoxiaoNeural（自然中文女声）
- 优势：免费、无需 GPU、中文自然度高
